## Goal, constraints, and success criteria

Refactor the existing 774-line wireless pattern menu into a thin native-menu integration using an **unattached PatternGridBlockEntity state adapter**, the **native server constructor**, and the **official native EMI handler**. Keep the native wireless Grid / NetworkItemContext as the network authority. Preserve item-local drafts, all four pattern types, fuzzy mode, recipe results, processing alternatives, selected stonecutter recipe, native one-shot output-slot pattern copying, blank-pattern consumption and output replacement rules. Offline means empty/inactive network state and **server-enforced read-only editing**, not deletion of the saved draft.

Never place a block or register a phantom BE in a Level, block-entity map, chunk, ticker, or RS network. Never dirty a chunk or emit a block/neighbour update from adapter changes. Never attach the adapter's own mainNetworkNode to a real network. No GameTest probes, runtime-control scripts, screenshots, runClient/runServer, or world start/stop: user controls runtime. Existing uncommitted menu transfer overrides may be replaced. No scaffold, wrapper rewrite, dependency upgrades, or unrelated feature rewrite.

Success: native server state drives slots and properties; official EMI bridge fills via native C2S/menu/BE methods; no copied encoding/recipe-transfer loops; disconnect empties visible network resources and blocks editing, reconnect rebuilds strategies/watchers without old listeners or duplicate opening energy; close/page switch persists only the actual terminal item and removes watcher exactly once. Build success and static review must be distinguished from runtime tests not performed.
